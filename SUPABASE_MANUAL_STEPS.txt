141GANG — ЧТО НУЖНО СДЕЛАТЬ В SUPABASE
Проект: ncqqilfkgdvnkgsiheok

Эта инструкция относится к обновлениям безопасности сайта и Twitch-доступа.

ВАЖНО
1. Сначала разверните Edge Function, затем сразу загрузите обновлённые файлы сайта,
   и только после этого применяйте SQL. Так публичные медиа не пропадут на время
   обновления.
2. SQL-файлы выполняйте целиком и строго по порядку ниже.
3. Все действия выполняйте в проекте ncqqilfkgdvnkgsiheok.
4. Не добавляйте service_role key в config.js, HTML или любой клиентский JavaScript.

ШАГ 1. РАЗВЕРНУТЬ EDGE FUNCTION public-media

Откройте терминал в корне проекта и выполните:

supabase login
supabase functions deploy public-media --project-ref ncqqilfkgdvnkgsiheok --no-verify-jwt

Исходник функции находится здесь:
supabase/functions/public-media/index.ts

Флаг --no-verify-jwt нужен намеренно: опубликованные материалы смотрят обычные
зрители без входа. Сама функция выдаёт только опубликованные записи, не отдаёт
UUID пользователя и внутренний storage_path, проверяет Origin и создаёт короткие
временные ссылки на файлы. SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY для функции
Supabase предоставляет автоматически; вручную помещать эти ключи на сайт нельзя.

Если сайт будет работать не только на 141gang.ru/www.141gang.ru, добавьте новый
домен в allowedOrigins внутри supabase/functions/public-media/index.ts и повторно
разверните функцию.

ШАГ 2. ЗАГРУЗИТЬ ОБНОВЛЁННЫЙ САЙТ НА ХОСТИНГ

После успешного развёртывания public-media загрузите на хостинг текущую версию
проекта. Новый клиент уже обращается к защищённой Edge Function и не пытается
показывать внутренние пути Storage зрителям.

ШАГ 3. ОБНОВИТЬ ТАБЛИЦЫ И ПОЛИТИКИ МЕДИА

Откройте Supabase Dashboard -> SQL Editor -> New query.
По очереди вставьте содержимое каждого файла и нажмите Run:

1) supabase/media_submissions.sql
2) supabase/allow_authenticated_content_submissions.sql
3) supabase/private_media_delivery.sql

Каждый запрос должен завершиться без ошибок до запуска следующего.
После этих запросов бакет stream-submissions станет приватным, а пользователи
смогут работать только со своими материалами, пока те находятся на модерации.

ШАГ 4. СКРЫТЬ СЛУЖЕБНЫЕ UUID И УЖЕСТОЧИТЬ ДОСТУП

В SQL Editor выполните целиком:

4) supabase/security_hardening.sql

Этот файл закрывает таблицу site_admins от браузера и запрещает выдавать
created_by из публичного каталога игр.

ШАГ 5. ЗАКРЫТЬ ЛИШНИЕ ПРАВА НА RPC

Этот файл обязательно запускается ПОСЛЕДНИМ, после всех остальных миграций:

5) supabase/rpc_execute_hardening.sql

Если Supabase сообщает, что какой-либо функции не существует, сначала примените
миграцию, которая создаёт эту функцию. Не удаляйте проблемную строку из файла:
иначе соответствующая функция останется с непроверенными правами.

ШАГ 6. ОГРАНИЧИТЬ ПРЕДЛОЖЕНИЯ И ОЦЕНКИ TWITCH-ПРОФИЛЯМИ

В SQL Editor выполните целиком:

6) supabase/twitch_only_user_actions.sql

Этот файл добавляет серверную проверку Twitch-провайдера для предложений игр,
медиа и лайков/дизлайков. Администраторы и service_role сохраняют доступ.

ШАГ 7. ПРОВЕРИТЬ STORAGE

В Dashboard откройте Storage -> stream-submissions и убедитесь:

- Public bucket выключен (бакет Private).
- У anon нет политики SELECT для storage.objects этого бакета.
- Новые файлы сохраняются только в формате objects/<случайное-имя>.<расширение>.

Старые файлы, путь которых содержит UUID пользователя или имеет старую структуру,
Edge Function намеренно не публикует. Их безопаснее повторно загрузить через
обновлённый сайт и заново опубликовать. Не возвращайте бакету публичный режим ради
старых ссылок.

ШАГ 7. ФИНАЛЬНАЯ ПРОВЕРКА

Проверьте сайт в приватном окне браузера без авторизации:

1. Каталог игр загружается, но в ответах Supabase нет created_by.
2. Список опубликованных медиа загружается через /functions/v1/public-media.
3. В ответе public-media нет created_by и storage_path.
4. Прямая ссылка вида
   /storage/v1/object/public/stream-submissions/...
   не открывает файл и не позволяет листать бакет.
5. Авторизованный зритель может отправить материал и удалить только свой материал
   со статусом pending.
6. Администратор по-прежнему видит очередь модерации и может публиковать материалы.

Если все шесть проверок пройдены, ручная настройка Supabase завершена.
